## 1. How the data is structured (recap)

| Layer | Table | Holds | Evidence table |
|---|---|---|---|
| Model | `model_specifications` (31 rows) | Facts that are the same in every generation (body wood, fret count, scale length…) | `model_spec_sources` |
| Generation | `model_gen_specs` (38 rows, one per model × generation) | Facts that changed between generations (pickups, logos, tuners, knobs…) | `model_gen_spec_sources` |
| Dropdown values | `ref_values` (prefix codes such as `COL-`, `SKN-`, `SCT-`) | Every option the forms offer. The specs store these codes. | — |
| Wizard rules | `generation_indicators` | "If you see X, it's Gen Y" rules | `generation_indicator_sources` |
| Autofill rules | `components` + `component_implied_specs` | "If field A = X (and field B = Y), then field C = Z" | — |
| Archive | `source_materials` (26 rows) | Catalogues, magazines, IPO filings and so on | — |

**Generation codes:** GEN-0005 = Gen 0.5, GEN-0001 = Gen 1, GEN-0002 = Gen 2, GEN-0003 = Gen 3, GEN-0004 = Pre-production.

**Effective value of a field:** use the generation-layer value if it's set, otherwise the model-layer value. A field's evidence is its citations on both layers.

## 2. Changes made in this session

### 2.1 Evidence system (new): migration `evidence_types_and_citation_links`
- **Two new source-type codes in `ref_values`:**
  - `SCT-0006` Registry Verified
  - `SCT-0007` Inherited
- **New table `public.evidence_types`** (RLS on, readable by the public). Columns: `id` (FK to `ref_values`, the SCT code), `label`, `description` (hover text), `icon` (Tabler icon name), `colour`, `style` (`solid`|`outline`), `strength_rank`, `link_target` (`archive_source`|`registry_guitar`|`parent_model`|`none`).

| id | label | icon | colour | style | rank | link_target |
|---|---|---|---|---|---|---|
| SCT-0001 | Archive: quote | quote | #185FA5 | solid | 1 | archive_source |
| SCT-0003 | Archive: photo | photo | #0F6E56 | solid | 2 | archive_source |
| SCT-0006 | Registry verified | database | #534AB7 | solid | 3 | registry_guitar |
| SCT-0004 | Owner inspection | user-check | #993C1D | solid | 4 | registry_guitar |
| SCT-0005 | Dealer documentation | receipt | #5F5E5A | solid | 5 | archive_source |
| SCT-0002 | Inferred | bulb | #BA7517 | outline | 6 | archive_source |
| SCT-0007 | Inherited | git-branch | #993556 | outline | 7 | parent_model |

- **New columns on both `model_spec_sources` and `model_gen_spec_sources`:**
  - `inherited_from_model_id uuid` (FK to `model_specifications`)
  - `inherited_from_generation text` (FK to `ref_values`, a GEN code)
  - `guitar_ids uuid[]`: the registry guitars that back an owner-inspection or registry-verified citation
- `source_material_id` is now **nullable** on both citation tables. Check constraints `mss_needs_evidence` and `mgss_needs_evidence` require at least one of: `source_material_id`, `guitar_ids` or `inherited_from_model_id`.
- **Reclassified 68 citations from Inferred to Inherited** (62 model-level, 6 generation-level). These are the excerpts that explicitly say "inherits … from [model]". Each was linked to its parent through `inherited_from_model_id`, and the generation-level ones also got `inherited_from_generation`.

### 2.2 Switch-knob split (O-ring count)
- **New codes:**
  - `SKN-0007` "Factory — Cylindrical with 1× O-ring" (5-way blade models)
  - `SKN-0008` "Factory — Cylindrical with 2× O-rings" (3-way toggle models)
- `SKN-0001` "Cylindrical with O-rings" is now **retired** (`is_active=false`, with a note added to its descriptor). No rows use it any more.
- **26 `model_gen_specs` rows re-mapped by switch type:**
  - 11 blade rows → SKN-0007 (Chaos 1/2 and HT, F2, F3, SF-3, Species 1/2)
  - 15 toggle rows → SKN-0008 (F1, F1HT, X1, SF-1, Matrix, X-Treme, FD/XD-Tox and their HTs)
- Guitar `F2-00024` → SKN-0007.
- **Evidence for the re-map:**
  - Owner-inspection citations (SCT-0004) for F2 (1× O-ring) and F1 Gen 0.5 (2× O-rings).
  - Every other re-mapped row has an **Inferred** citation marked "not yet photo-verified".
- **Wizard rule** `generation_indicators` for switch_knob Gen 1 split into a "2× O-rings" rule (toggle) and a new "1× O-ring" rule (blade).
- **Four new `components` autofill rules.** Each uses `trigger_field=switch_type` and `trigger_field_2=generation`, and implies a `switch_knob` value:
  - Blade + Gen 0.5 → SKN-0007
  - Blade + Gen 1 → SKN-0007
  - Toggle (Standard) + Gen 0.5 → SKN-0008
  - Toggle (Japanese) + Gen 1 → SKN-0008

  ⚠️ **The site code must accept `generation` as a trigger field.** The existing rules only trigger on spec fields.

## 3. Website work needed (build to catch up)

### 3.1 Evidence icon clusters (agreed design)
- Every spec field on model pages gets a **cluster of small circular icons**, each about the height of the text, **one per evidence type** present (gen and model layers combined).
- **Order:** by `strength_rank`.
- **Style:**
  - `solid` = filled circle in `colour` with a white icon
  - `outline` = ring and icon in `colour`
- **Count badge** when a type has more than one citation (for example ×3).
- **No citations at all:** show a dashed grey ring with a question-mark icon ("Unsourced").
- **Hover (desktop) / tap (mobile):** a panel listing **each citation of that type as its own link**, with the excerpt and page:
  - `archive_source` → the archive page for `source_material_id` (plus the page reference)
  - `registry_guitar` → the registry page of each guitar in `guitar_ids`
  - `parent_model` → the parent model's field (`inherited_from_model_id` + `inherited_from_generation`) and that field's own evidence
  - no link possible → show `evidence_types.description`
- Every panel includes a link to the methodology page.
- Colours and icons must come from `evidence_types` (one source of truth) and stay the same everywhere on the site.

### 3.2 Methodology section (new, under Archive)
- A legend of the evidence icons, generated from `evidence_types`, styled like the existing colour guide.
- An explanation of the archive and sourcing approach: source types, what "inferred" and "inherited" mean, how registry verification works (minimum number of approved examples, still to be decided), and how corrections are made.

### 3.3 Dropdowns and wizard
- Dropdowns must hide `ref_values` where `is_active=false` (SKN-0001).
- Check whether any labels are typed into the code rather than read from `ref_values`.
- Wizard and autofill: switch knob is now determined by switch type and generation (see 2.2).

### 3.4 Design target for submissions (build toward, not yet built)
- The wizard **autofills the submission form** using the `components` rules. Each autofilled field is flagged for the owner to check against their guitar.
- Each field offers an **"Other / aftermarket"** option.
- Store a **status per field** for each submitted guitar: the value suggested, the value the owner chose, and the outcome (confirmed factory, different factory option, or aftermarket).
- The guitar's **Stock vs Modified** status is **worked out** from those per-field outcomes, not entered by hand. This feeds the future **valuation engine**, so which parts were changed matters, not just a yes/no flag.
- The current `guitars` table copies spec fields as flat columns and can't record any of this. Design the new structure alongside the members area (owner claims).
